# Wave 0: numbers and hygiene (2026-09-12)

Branch: build/wave-0. Authority: docs/DESIGN-EXPERIENCE-2026-09-10.md (Ten moves rows 1, 2, 3, 6, 9, 10; Build order row 0) and docs/experience-design/rulings-packet-2026-09-10.md. Research: docs/PERSONA-RESEARCH-2026-09-10.md cross-cutting points 6 and 7.

## 1. What shipped

**Item 1, instrumentation carries the path.** src/utils/analytics.ts track() now attaches the reader's path (from dw_setup.persona) and, for new_to_faith readers, the current journey day (from dw_pathway_progress.currentDay) to every tracked event, so no call site has to remember either value. The TRACKED_EVENTS allowlist gained the comfort_* names, journey_day_open and journey_day_complete, pastor_prompt, and the deeper_study event names from the specs. src/utils/tracked-events.ts holds the allowlist as its own module. netlify/functions/track-activity.js and its new netlify/functions/lib/activity-rows.js accept path and journey_day on each event and write them through to public.activity_events. supabase/migrations/20260912_activity_events_path_journey_day.sql adds the two columns, additive and nullable. journey_day_open and journey_day_complete now fire from the existing Day N surface (open and Mark Complete) in HomeScreen.tsx; the other new event names are wired for later waves' emit sites.

**Item 2, dw_read_days on the local en-CA date axis.** src/utils/readDays.ts is a new module holding a localStorage record of the local dates, computed with toLocaleDateString('en-CA'), on which a genuine reading interaction happened: Mark as read, Day N Mark Complete, audio play on a passage, or a highlight/journal save. src/utils/readDaysMerge.ts merges new dates into whatever localStorage already holds rather than rebuilding from React state, and the record syncs through the existing misc channel (syncMisc) alongside the other dw_* keys. src/utils/behavior.ts:54 now computes the local date with the same en-CA helper instead of the previous axis. Where Home printed a day count from the streak, GreetingSection and the header streak chip in HomeScreen.tsx now print the dw_read_days count; deeper_study's greeting stays name-only, unchanged. recordStreakToday() no longer fires unconditionally on Home mount (the block that used to run in HomeScreen.tsx's mount effect is gone); it now fires from the same genuine-interaction call sites as the read-day record, so a streak milestone follows an actual read, never an open.

**Item 3, the Read tap stops crediting a plan day.** handleRead in src/screens/HomeScreen.tsx still opens the passage and tracks the tap, but the call to markPlanDayComplete has been removed from that path. Completion now comes only from the explicit complete actions: Mark as read, Day N Mark Complete, and the pathway day. See the note below on the completion-count drop this causes.

**Item 4, the seeded campus counter is gone.** src/sections/CampusCountSection.tsx's getCampusReaderCount seed generator is removed; the section now renders only the campusStats.readingToday value the API actually returned for the user's campus, and renders nothing if that value is absent. src/sections/CongregationStatsSection.tsx is the same: no invented numbers. Both files are kept. campus_count is dropped from sectionOrder wherever it would now render empty, so no blank card shows.

**Item 5, decorative emoji glyphs are gone app-wide.** Removed: the flame before "Milestone Reached" and the "You're amazing." sentence in src/sections/GreetingSection.tsx, the 56px flame in src/screens/HomeScreen.tsx, the glyph in src/components/DoneCelebration.tsx, and CampusCountSection's flame entity. A repo-wide grep for decorative emoji glyphs used as UI in src turned up no further instances outside the deliberate non-targets listed below. Lucide icons or nothing replaces them; the milestone words themselves stay.

**Item 6, es and pt push templates.** netlify/functions/lib/push-templates.js (new module, imported by netlify/functions/push-send.js) now carries es and pt sets of the same seven neutral scripture-snippet templates and VERSE_SNIPPETS entries that already existed for en and id, all free of streak and guilt language. Template selection honours push_subscriptions.lang for es and pt the same way it already did for en and id. src/utils/push-templates.test.ts asserts that no template or snippet in any language contains streak, racha, sequência, miss, lose or break.

**Item 7, i18n.** Every new or changed UI string introduced by items 1 through 6 (the read-day-based day count, any changed labels) has a key in src/utils/i18n.ts with en, es, pt and id rows added in this same commit, following the file's existing \uXXXX-escape convention.

## 3. Completion counts will drop

Completion counts will DROP the week this ships. The Read tap used to mark the plan day complete on open; completion now comes only from Mark as read, Mark Complete and the pathway day. The fall in completions is the fix working, not a regression.

## 4. The day-number change

Home now prints the dw_read_days count. The record starts empty and is deliberately NOT back-filled from the streak, so a reader mid-streak sees the count begin again at their next real reading; bestCount survives via streak.ts:82.

## 5. The re-timed push ask

recordStreakToday no longer fires on Home mount; it now fires only from a genuine reading interaction (Mark as read, Day N Mark Complete, audio play, a highlight or journal save), the same trigger set that writes a dw_read_days entry. The dw-streak-recorded event that streak.ts dispatches on every recordStreakToday() call therefore now fires after the first genuine reading instead of on open. EmailNudgeCard listens for dw-streak-recorded to time the post-reading email hand-off card, so that card is re-timed by this change along with it. The separate native push permission ask in App.tsx is unaffected: it is keyed on dw-reading-completed / dw_reading_done, a different, already evidence-timed signal, not on dw-streak-recorded.

## 6. The migration is not applied by this branch

supabase/migrations/20260912_activity_events_path_journey_day.sql is NOT applied by this branch and must be hand-applied with a ledger row before the deploy. Events carry path and journey_day as null-tolerant columns, so the function is safe either way: if it deploys before the migration is applied, the insert simply omits or nulls those two columns until the migration lands.

## 7. The server no longer keeps a second event-name allowlist

netlify/functions/track-activity.js and its new netlify/functions/lib/activity-rows.js no longer duplicate a server-side event-name allowlist; the client's TRACKED_EVENTS allowlist in src/utils/analytics.ts is the single name gate, and the server only validates shape (name pattern, path, journey_day, detail length). This means event names like daily_reading and plan_start, which previously never reached activity_events because an old server-side list silently dropped them, now reach the table for the first time. Event volume in activity_events will rise as a result; this is expected, not a bug.

## 8. es and pt push templates need approval before send

The es and pt push templates and verse snippets are Claude-drafted and need Ashley's approval before the push cron sends them. Push cannot be verified on a deploy preview: pushSupported() allowlists futuresdailyword.com, www.futuresdailyword.com and localhost only, so a preview URL will never register for push regardless of these changes.
